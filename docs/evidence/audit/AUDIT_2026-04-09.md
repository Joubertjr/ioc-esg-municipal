## Resumo Executivo

O projeto está em estágio avançado de desenvolvimento com 15 coletores implementados, 17/17 ODS mapeados, 7 páginas frontend e infraestrutura de produção completa. A base de código é sólida em várias dimensões — TypeScript strict sem `any`, Zod em todos os coletores, autenticação JWT com CSRF e rate limiting. Foram identificados **1 achado crítico de segurança** (IDOR em rotas de alto valor), **1 vulnerabilidade crítica de dependência** (axios SSRF), e lacunas de cobertura de testes para 9 dos 15 ODS mappers. O código de avaliação LongMemEval adicionado nos últimos 5 commits (1.288 linhas) reside dentro de `backend/` sem isolamento adequado do código de produção.

## 🔴 Crítico

### C1 — IDOR: Rotas sem isolamento por município autenticado

**Dimensão:** Segurança / Arquitetura

**Localização:**

- `backend/routes/reports.ts` — linha inteira: rota sem nenhum `requireRole` nem verificação de `req.user.municipalityId`
- `backend/routes/recommendations.ts` — sem verificação de propriedade do município
- `backend/routes/ods.ts` — `requireRole` aplicado apenas no endpoint `/compare` (linha 120), não no `GET /:ibgeCode` principal

**Evidência:**

```
backend/index.ts:116: app.use("/api/ods", authenticateToken, odsRouter);
backend/index.ts:118: app.use("/api/reports", authenticateToken, reportsRouter);
backend/index.ts:120: app.use("/api/recommendations", authenticateToken, recommendationsRouter);
```

`authenticateToken` valida que o JWT é válido, mas **não impede** que um prefeito autenticado de Florianópolis (ibgeCode `4205407`) acesse o relatório ESG, score ODS ou recomendações de São Paulo (`3550308`). A rota `backend/routes/simulator.ts:190` tem o padrão correto: `if (req.user!.role !== "admin" && req.user!.municipalityId !== municipality.id)`. Este padrão não foi replicado nos outros endpoints.

**Risco:** Um usuário `prefeito` pode fazer IDOR (Insecure Direct Object Reference) enumerando ibgeCodes e lendo dados confidenciais de qualquer município.

**Correção sugerida:** Adicionar middleware `requireMunicipalityScope` reutilizável similar ao de `simulator.ts:190` nas rotas `reports`, `recommendations` e `GET /api/ods/:ibgeCode`.

### C2 — Vulnerabilidade crítica: axios SSRF (CVE GHSA-3p68-rc4w-qgx5)

**Dimensão:** Segurança

**Localização:** `package.json` — `axios@1.14.0` (direto)

**Evidência:** `pnpm audit` reporta:

```
critical: Axios has a NO_PROXY Hostname Normalization Bypass Leads to SSRF
Package: axios
Vulnerable versions: <1.15.0
Patched versions: >=1.15.0
Path: . > axios@1.14.0
```

**Risco:** Vulnerabilidade de Server-Side Request Forgery em ambiente de produção que faz chamadas a APIs governamentais externas. Upgrade imediato para `axios@>=1.15.0`.

## 🟡 Aviso

### A1 — 1.288 linhas de código de avaliação dentro do backend de produção

**Dimensão:** Arquitetura

**Localização:** `backend/evaluation/longmemeval/` (5 arquivos, 1.288 linhas)

**Evidência:** Adicionados no commit `76c96e6` e `ad0c9f0`:

```
backend/evaluation/longmemeval/dataset-generator.ts  519 linhas
backend/evaluation/longmemeval/runner.ts             327 linhas
backend/evaluation/longmemeval/judge.ts              207 linhas
backend/evaluation/longmemeval/reporter.ts           153 linhas
backend/evaluation/longmemeval/types.ts               77 linhas
```

O código não está importado em `backend/index.ts` (verificado), mas reside no mesmo pacote TypeScript, será incluído no `tsc build`, e aumenta a superfície de ataque sem benefício. A convenção do projeto coloca utilitários de pesquisa em `scripts/` ou pacotes separados.

**Correção:** Mover para `tools/evaluation/` ou excluir do `tsconfig.json` via `exclude`.

---

### A2 — Bull Queue declarado na ADR-001 mas não implementado

**Dimensão:** Arquitetura / ADR

**Localização:** `docs/decisions/ADR-001-stack-tecnologica.md`

**Evidência:** ADR-001 define "Filas: Bull (coleta agendada, processamento async)" como parte da stack aprovada. Pesquisa em `backend/**/*.ts` por `bull|queue|Queue` retornou 0 resultados. A coleta em batch é feita de forma síncrona em `POST /api/agents/batch/:ibgeCode`.

**Impacto:** Com 295 municípios, coleta batch síncrona pode causar timeout HTTP e bloquear o event loop durante até 15 chamadas externas paralelas com timeout de 5s cada.

---

### A3 — 10/15 coletores usam dados JSON estáticos (não chamadas de API em tempo real)

**Dimensão:** Dados/ESG

**Localização:** `shared/data/*.json`

**Evidência:** Apenas IBGE, SICONFI, DATASUS, INPE e PNCP fazem chamadas HTTP ao vivo. Os demais 10 coletores (ANA, ANATEL, ANEEL, CONVENIOS, INEP, SNIS, SNIS_RS, TSE, SISVAN, IEPS) carregam arquivos JSON estáticos com dados de 2021–2024.

Situação mais crítica:

- `ieps_2021.json` — dados de 2021, defasagem de 4–5 anos para indicadores de saúde do ODS 3
- `snis_2022.json` / `snis_rs_2022.json` — 284/295 municípios cobertos (11 municípios SC sem cobertura de ODS 6 e ODS 12)

Os coletores documentam a limitação nos comentários (ex: `ieps_collector.ts:31`), mas o sistema não sinaliza a defasagem ao usuário final no score ESG.

---

### A4 — 9/15 ODS mappers sem testes unitários

**Dimensão:** Testes

**Localização:** `tests/unit/agents/`

**Evidência:** Os seguintes agentes têm testes de coletor mas **não têm** testes de mapper ODS:

- ANA (ODS 14), ANATEL (ODS 9), ANEEL (ODS 7), CONVENIOS (ODS 17)
- INPE (ODS 13/15), PNCP (ODS 16), SNIS (ODS 6), SNIS_RS (ODS 12)
- TSE (ODS 5), SISVAN (ODS 2)

Os mappers contêm lógica de normalização crítica (inversão de indicadores, cálculo de scores 0-100). Uma regressão silenciosa nos pesos ou thresholds não seria detectada.

**Comparação:** IBGE, SICONFI, DATASUS, INEP e IEPS têm testes de mapper completos — é o padrão esperado.

---

### A5 — Vulnerabilidades de dependência: 4 high (minimatch, lodash, esbuild)

**Dimensão:** Segurança

**Evidência:** `pnpm audit` (8 vulnerabilidades total):

```
high: minimatch ReDoS (3 variantes) — >= 9.0.0 < 9.0.7 (via @typescript-eslint)
high: lodash Code Injection via _.template (via dependências de build)
moderate: esbuild <=0.24.2 (via vitest/vite — dev only)
moderate: vite <=6.4.1 (via @vitest/ui — dev only)
```

As vulnerabilidades `esbuild` e `vite` são **somente dev** e não afetam produção. `minimatch` e `lodash` são transitivas de `@typescript-eslint` — risco moderado em pipeline CI/CD, não em runtime.

---

### A6 — Sem tag de staleness de dados no score ESG

**Dimensão:** Dados/ESG

**Localização:** `backend/services/ods/ods_score_service.ts`, `shared/types/domain/ods.ts`

**Evidência:** O tipo `OdsIndicator` retorna `referenceDate`, mas a UI (`frontend/pages/dashboard/`) não exibe aviso visual quando `referenceDate` é anterior a 2 anos. Um prefeito vendo score ODS 3 calculado com dados IEPS de 2021 não tem como saber que os dados têm 4+ anos de defasagem.

## 🟢 Positivo

### P1 — TypeScript strict: zero `any`, zero supressões

O codebase de produção não contém nenhuma ocorrência de `: any` nem `@ts-ignore`/`@ts-expect-error`. Todo o código de domínio usa tipos explícitos com `unknown` + type guards quando necessário. O único match de "any" encontrado foi uma string de log (`"No data from any source"`) — falso positivo confirmado.

### P2 — Padrão de coletor consistente e robusto

Todos os 15 coletores seguem o mesmo padrão arquitetural:

1. Validação Zod na carga do módulo (`safeParse` com `logger.error` em falha)
2. Falha graceful (retorna `null` em vez de lançar exceção)
3. `ibgeToSiconfi()` para conversão de código
4. Métodos `collect()` e `collectBatch()` padronizados

Os coletores HTTP (IBGE, SICONFI, DATASUS, INPE, PNCP) adicionalmente implementam cache Redis, retry com backoff exponencial e timeout configurável via `API_CONFIGS`.

### P3 — Segurança HTTP exemplar

- Helmet com CSP estrita diferenciada por ambiente (dev vs prod)
- Tokens JWT com rotação de refresh token e revogação imediata pós-uso (`auth_service.ts:224`)
- CSRF check via `Origin`/`Referer` para métodos mutantes (`auth.ts:verifyCsrf`)
- `.env` no `.gitignore` (verificado); `.env.example` mantido versionado
- Rate limiting por rota (`generalLimiter`, `batchLimiter`)
- Guarda contra JWT_SECRET placeholder em produção (`auth.ts:31-37`)
- Nenhum `eval(`, `exec(` ou `dangerouslySetInnerHTML` encontrado

### P4 — Cobertura de testes de serviço e rotas completa

Todos os 7 serviços principais têm testes unitários correspondentes. Todas as 8 rotas têm testes de rota. 4 suites de integração cobrem auth, ODS, simulator, benchmarks e municipalities.

### P5 — 17/17 ODS com indicadores mapeados

Todos os 17 ODS da ONU têm pelo menos 1 indicador ativo mapeado por pelo menos 1 dos 15 coletores. Verificado via grep em `*_ods_mapper.ts`: `odsNumber: 1` a `odsNumber: 17` todos presentes.

### P6 — Infraestrutura de produção completa

Dockerfile multi-stage (Node 20, dumb-init, non-root, healthcheck), nginx com headers de segurança, GitHub Actions CI/CD, graceful shutdown com timeout de 10s.
