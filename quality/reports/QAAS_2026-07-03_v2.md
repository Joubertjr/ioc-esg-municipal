### CRÍTICO

#### C-01 — protobufjs override insuficiente: versão 7.5.5 ainda vulnerável

**Dimensão:** G (Segurança e supply chain)

**Evidência (fato comprovado — executado):**

- `package.json` `pnpm.overrides`: `"protobufjs@<7.5.5": "7.5.5"` — seletor captura apenas versões `< 7.5.5`; a versão instalada é exatamente `7.5.5`, **fora do seletor**, portanto o override não teve efeito
- `pnpm audit` output confirmado: `protobufjs@7.5.5` via `. > @huggingface/transformers@4.0.1 > onnxruntime-web@1.25.0-dev > protobufjs@7.5.5`

CVEs ativos com protobufjs 7.5.5 (todos requerem versão superior à instalada):

- GHSA-66ff-xgx4-vchm: Code injection via bytes field defaults — requer `>=7.5.6`
- GHSA-75px-5xx7-5xc7: Code generation gadget after prototype pollution — requer `>=7.5.6`
- GHSA-jvwf-75h9-cwgg: Process-wide DoS via unsafe option paths — requer `>=7.5.6`
- GHSA-685m-2w69-288q: DoS via unbounded recursion — requer `>=7.5.6`
- GHSA-wcpc-wj8m-hjx6: DoS via unbounded Any expansion — requer `>=7.6.1`
- GHSA-jggg-4jg4-v7c6: DoS via recursive JSON descriptor expansion — requer `>=7.5.8`
- GHSA-f38q-mgvj-vph7: Schema names shadow runtime properties — requer `>=7.6.3`

**`@huggingface/transformers` está em `dependencies` (produção) em `package.json`.**

**Cenário de falha:** CVEs de code injection e prototype pollution afetam o runtime do servidor de produção sempre que `@huggingface/transformers` parsear modelos ONNX via protobufjs.

**Impacto potencial:** Execução de código arbitrário / prototype pollution no container de produção.

**Recomendação:** Substituir o override atual pelo correto:

```json
"pnpm": {
  "overrides": {
    "protobufjs": ">=7.6.3"
  }
}
```

Remover a entrada `"protobufjs@<7.5.5": "7.5.5"` — o seletor versioned não cobre a versão instalada.

**Dimensão:** K (CI/CD e governança)

**Evidência (fato comprovado):** `.github/workflows/main.yml` não contém `madge` em nenhum step — verificado por grep completo no arquivo.

**Contexto:** madge passou localmente (0 ciclos confirmado por execução), mas qualquer nova feature pode reintroduzir ciclos sem detecção automática em CI.

```yaml
- name: Circular dependency check

```

#### NEW-G-01 — form-data@4.0.5 CRLF injection via axios@1.18.1 (produção)

**Dimensão:** G (Segurança e supply chain)

**Evidência (fato comprovado — executado):** `pnpm audit` — GHSA-hmw2-7cc7-3qxx — `form-data: CRLF injection via unescaped multipart field names and filenames`. Versão vulnerável: `>=4.0.0 <4.0.6`. Versão instalada: `4.0.5`. Caminho: `. > axios@1.18.1 > form-data@4.0.5`.

**`axios` está em `dependencies` (produção).** Paths via supertest/superagent são devDeps.

**Cenário de falha:** Coletores de API que enviam requisições com form-data (POST multipart) para APIs governamentais com field names não sanitizados podem injetar headers HTTP arbitrários.

**Impacto potencial:** CRLF injection em requisições multipart — baixo se os coletores usam apenas GET, maior se houver POST com form fields.

**Recomendação:** Adicionar override em `package.json`:

```json
"pnpm": {
  "overrides": {
    "form-data": ">=4.0.6"
  }
}
```

Depois executar `pnpm install` para aplicar.

### MÉDIO

#### M-02 — siconfi integration tests completamente skipped (5 testes)

**Dimensão:** F (Integrações, APIs e contratos)

**Evidência:** `tests/integration/agents/siconfi_integration.test.ts:14` — `describe.skipIf(!process.env["SICONFI_INTEGRATION"])`. CI nunca define `SICONFI_INTEGRATION`. SICONFI é a fonte de FPM — o dado financeiro central da plataforma.

**Cenário de falha:** Mudança no formato de resposta da API SICONFI (ou no parsing IBGE→SICONFI 7→6 dígitos) não é detectada automaticamente em CI.

**Recomendação:** Implementar mock HTTP (msw ou nock) com payload gravado para os 5 testes; manter testes contra API real via `SICONFI_INTEGRATION=1` como opt-in manual.

#### M-03 — Prisma error em stdout de testes unitários

**Dimensão:** E (Efetividade dos testes)

**Evidência (fato comprovado — executado):** `npx vitest run` produz no stdout de `tests/unit/services/ods_score_service.test.ts`:

```
prisma:error — Authentication failed against database server at `localhost`...
```

Origem: `backend/services/ingestion/ods_score_reader.ts:35` — `prisma.municipality.findUnique()` chamado sem mock em contexto de teste unitário.

Testes passam porque a falha é capturada em try/catch, mas um teste unitário depende silenciosamente do comportamento de fallback de um erro de infra.

**Recomendação:** Adicionar `vi.mock("../../../backend/services/ingestion/ods_score_reader.js", ...)` no `ods_score_service.test.ts`.

#### M-04 — Sem gate de cobertura mínima de testes no CI

**Dimensão:** K (CI/CD e governança)

**Evidência:** `.github/workflows/main.yml` não contém `--coverage` ou threshold de cobertura. `vitest.config.ts` sem `coverage.thresholds`. Código crítico novo pode ser mergeado sem testes sem detecção.

**Recomendação:** Adicionar em `vitest.config.ts`:

```typescript
coverage: {
  provider: 'v8',
  thresholds: { lines: 80, include: ['backend/services/**'] }
}
```

E no CI: substituir `pnpm test:unit` por `pnpm test:coverage`.
